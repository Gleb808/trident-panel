# Проверки первой версии

Дата: 16 сентября 2026. Среда: Windows, Node.js 24.19.0, встроенная SQLite 3.53.3.

## Автоматические проверки

Команда: `node --test --test-isolation=none test/*.test.mjs`

**7 тестовых сценариев прошли.**

1. Пересечения портов и диапазонов, зарезервированные порты, некорректные числа и домены.
2. Независимые ключи, запись/чтение шифрованной БД, частичный перевыпуск, отсутствие секретов в публичных моделях.
3. Истечение срока убирает пользователя из всех трёх серверных конфигов; при нуле пользователей нет открытого forward proxy.
4. Согласованность клиентских/серверных паролей, UUID, REALITY-ключей и разных локальных SOCKS-портов.
5. Структура ZIP и состав файлов. Дополнительно архив распакован штатным PowerShell Expand-Archive.
6. Агент: повторное применение не нужно при той же рабочей ревизии, ошибка валидации не активирует конфиги, ошибка применения вызывает откат. Адаптер в этом тесте имитируется, Linux-службы не запускаются.
7. Реальный HTTP API: создание администратора, авторизация, CSRF/Origin/Host, пользователь, ZIP, запрет выдачи до применения, отзыв ссылки, истечение срока и чтение сохранённых данных.

## Проверка настоящими клиентами

- **Xray-core 26.3.27 / Windows amd64**: `run -test -config server-xray.json` → `Configuration OK.`
- **Xray-core 26.3.27 / Windows amd64**: `run -test -config vless.json` → `Configuration OK.`
- **mieru 3.37.0 / Windows amd64**: `apply config mieru.json` в изолированный `MIERU_CONFIG_FILE` завершился с кодом 0.

Бинарники получены из официальных GitHub Releases. Это проверка принятия конфигурации, а не прохождения трафика через VPS.

## Браузер

Дополнительно проверено резервное копирование работающей SQLite-базы через Backup API и чтение восстановленной копии вместе с ключом: все 5 демонстрационных записей доступны.

Проверены вход, создание пользователя с автоматическим открытием трёх конфигов, форма настроек, видимое сообщение о конфликте портов, настольная и мобильная компоновка (390×844), карточки пользователей на телефоне. В консоли браузера после проверки не было предупреждений и ошибок.

Скриншоты используют вымышленные демонстрационные записи; поставляемая панель при первом запуске пустая.

## Автоматическая установка Ubuntu 24.04 — 17 сентября 2026

Workflow [`Ubuntu 24.04 installation`](.github/workflows/ubuntu-install.yml) **прошёл** на Ubuntu 24.04/amd64 с Node.js 24.21.0: [запуск 35141381318](https://github.com/Gleb808/trident-panel/actions/runs/35141381318), ревизия `d9a61be8f2dca836e5554a40b6028176f803d918`.

- Bash syntax и ShellCheck.
- Скачивание архива репозитория и четырёх настоящих релизов, сверка закреплённых SHA256.
- Проверка версий Node/Xray/mita/Caddy и наличия модуля forward_proxy.
- Установка пользователя, каталогов и systemd units, запуск backend и HTTP readiness.
- Все семь сценариев приложения на Linux.
- Проверка первичного состояния без администратора, владельца/прав файлов, loopback-порта, перезапуска службы.
- Отказ повторной установки без остановки работающей панели; отказ проверки неверной SHA256.
- Агент и протоколы до ручной настройки не запущены.

Это изолированный GitHub runner с Ubuntu, не пользовательский VPS. ACME и внешний трафик трёх протоколов в этом workflow не проверяются.

## Ещё не проверено

- Применение и откат через реальный Linux-адаптер агента.
- Запуск прокси-служб Caddy с forwardproxy naive, mita и Xray с реальными пользователями.
- ACME-сертификат, DNS, firewall, REALITY target из сети VPS.
- Реальный handshake/трафик всех протоколов, QUIC, приложения Android/iOS.
- Нагрузочные характеристики, отказ питания в середине применения, долговременная эксплуатация.

Эти проверки требуют Linux-стенда/VPS. В интерфейсе локальный запуск не выдаётся за подключённый сервер.
