# HTTP API TRIDENT 0.1

[К README](../README.md) · [Архитектура](ARCHITECTURE.md)

API обслуживает тот же origin, что и интерфейс. По умолчанию локальная точка — `http://127.0.0.1:8787`, публичная — `https://YOUR_DOMAIN:9443` через Caddy. Примеры ниже используют вымышленные значения; секреты нужно создавать на своей панели.

Сохранение через API изменяет желаемое состояние базы. Работающий Linux-агент применяет серверную часть асинхронно. Код `200` или `201` не означает, что три протокола уже приняли изменение.

## 1. Формат и авторизация

- JSON-запросы: `Content-Type: application/json`; тело должно быть объектом, максимум 32 KiB.
- Для всех запросов, кроме GET/HEAD, нужен `Origin`, точно совпадающий с origin панели, без завершающего `/`.
- Административные маршруты требуют cookie `trident_sid`. Изменяющие административные запросы дополнительно требуют заголовок `X-CSRF-Token` из ответа входа или `/api/session`.
- Отдельного bearer API-токена нет. CORS для сторонних сайтов не настроен.
- Ошибка имеет вид `{ "error": "Сообщение" }`. ZIP возвращается как `application/zip` с `Content-Disposition: attachment`.
- `Host` должен быть localhost с явным портом либо точно совпадать с настроенным `host:panelPort`. Для стандартного HTTPS-порта 443 текущая проверка также ожидает явный `:443`; не считайте произвольный reverse proxy совместимым без проверки.

`GET /healthz` отвечает только о доступности backend. Для состояния движков нужен `/api/overview`.

## 2. Создание администратора и сессия

| Метод и маршрут | Требования | Успешный ответ |
|---|---|---|
| `GET /healthz` | Проверка Host/Origin | `200 {"status":"ok"}` |
| `GET /api/session` | Без входа | `200 {setupRequired, authenticated, csrf?}` |
| `POST /api/setup` | Только loopback/localhost; администратор ещё не создан | `200 {csrf}` и cookie |
| `POST /api/login` | `Origin`, JSON | `200 {csrf}` и cookie |
| `POST /api/logout` | Сессия и CSRF | `200 {}`; сессия удаляется, cookie очищается |

Тело `/api/setup` и `/api/login`:

```json
{
  "password": "YOUR_ADMIN_PASSWORD"
}
```

При создании пароль должен содержать 12–256 символов. Повторный setup возвращает `409`; неправильный пароль входа — `401`. На вход и setup действует общий лимит 10 попыток в минуту на адрес соединения.

Пример Linux shell для существующего администратора:

```sh
umask 077
export TRIDENT_ORIGIN='http://127.0.0.1:8787'
# Подготовьте login.json с паролем локально; файл содержит секрет.
curl --silent --show-error --fail-with-body \
  --cookie-jar cookies.txt \
  --header "Origin: $TRIDENT_ORIGIN" \
  --header 'Content-Type: application/json' \
  --data-binary @login.json \
  "$TRIDENT_ORIGIN/api/login"
```

Сохраните `csrf` из ответа в переменную `TRIDENT_CSRF` для следующих примеров. `login.json` и `cookies.txt` содержат данные доступа и не должны попадать в репозиторий. Для запросов через публичный домен используйте его HTTPS-origin; setup по публичному домену запрещён.

Сессия действует 12 часов без автоматического продления. В cookie хранятся случайные данные; в базе — их SHA-256. Выход удаляет только текущую сессию, не все сессии администратора.

## 3. Обзор панели

### `GET /api/overview`

Требует сессию. Возвращает:

```json
{
  "users": [],
  "settings": {
    "host": "proxy.example.com",
    "naivePort": 443,
    "naiveQuic": false,
    "vlessPort": 8443,
    "mieruStart": 20000,
    "mieruEnd": 20009,
    "panelPort": 9443,
    "realitySni": "www.microsoft.com",
    "realityTargetPort": 443,
    "acmeEmail": "",
    "publicKey": "GENERATED_PUBLIC_KEY",
    "shortId": "GENERATED_SHORT_ID"
  },
  "status": {
    "desired": "HASH_OF_SERVER_FILES",
    "connected": false,
    "synced": false,
    "agent": null,
    "warnings": ["Укажите свой домен сервера в настройках"],
    "versions": {
      "xray": "26.3.27",
      "mieru": "3.37.0",
      "caddyNaive": "2.11.2-naive"
    }
  },
  "events": []
}
```

`users` идут в порядке добавления, новые первыми. Поиск, фильтрация и счётчики интерфейса вычисляются на клиенте; параметров пагинации API нет. `events` — последние 80 записей `{id, at, action, subject}`.

Если файл состояния существует, `agent` содержит `status`, `message`, `checkedAt`, `desiredRevision`, возможные `appliedRevision`, `services`, `rollback` и вычисленное `stale`. Не все поля присутствуют при каждом виде ошибки; клиент должен проверять их наличие.

`connected` означает свежесть проверки менее 90 секунд. `synced` означает совпадение текущей ревизии с применённой при свежем `status=applied`. Внешний handshake этим флагом не подтверждается.

## 4. Пользователи

### Общие поля

| Поле | Формат / ограничение | Создание | Частичное обновление |
|---|---|---|---|
| `name` | Непустая строка после trim, максимум 80 символов, без управляющих символов | Обязательно | Можно опустить |
| `note` | Строка после trim, максимум 500 символов | По умолчанию пусто | Можно опустить |
| `status` | `active` или `disabled` | Обязательно | Можно опустить |
| `expiresAt` | Разбираемая дата/время, сохраняется в ISO UTC; `null` для бессрочного | По умолчанию `null` | Можно опустить; `null` снимает срок |

Передавайте даты как ISO 8601 с `Z` или явным смещением. Для срока «по 16 октября включительно UTC» передайте `2026-10-16T23:59:59.999Z`. `expired` — вычисленный ответ, не допустимое значение для записи `status`.

### `POST /api/users`

Требует сессию, CSRF, Origin и JSON. Создаёт три независимых доступа и ссылку выдачи. Успех — `201` с публичной записью:

```json
{
  "id": "a1111111-1111-4111-8111-111111111111",
  "name": "Алексей",
  "note": "Тестовый доступ",
  "status": "active",
  "expiresAt": "2026-10-16T23:59:59.999Z",
  "createdAt": "2026-09-16T10:00:00.000Z",
  "effectiveStatus": "active"
}
```

Файл `user.json` для примера:

```json
{
  "name": "Алексей",
  "note": "Тестовый доступ",
  "status": "active",
  "expiresAt": "2026-10-16T23:59:59.999Z"
}
```

Запрос:

```sh
curl --silent --show-error --fail-with-body \
  --cookie cookies.txt \
  --header "Origin: $TRIDENT_ORIGIN" \
  --header "X-CSRF-Token: $TRIDENT_CSRF" \
  --header 'Content-Type: application/json' \
  --data-binary @user.json \
  "$TRIDENT_ORIGIN/api/users"
```

ID, секреты и токен создаёт сервер. Поля секретов, присланные в теле, не используются. Публичная запись не содержит паролей или UUID подключения VLESS: её `id` — идентификатор карточки, не VLESS UUID.

### `PUT /api/users/:id`

Принимает частичное обновление перечисленных полей; остальные сохраняются. Требует сессию, CSRF, Origin и JSON. Успех — `200` с публичной записью.

Отключение:

```json
{ "status": "disabled" }
```

Продление и включение:

```json
{
  "status": "active",
  "expiresAt": "2026-11-16T23:59:59.999Z"
}
```

Отдельного `/extend` нет. API-клиент вычисляет новую дату и отправляет `PUT`. Время действия на движках определяется следующим успешным применением.

### `DELETE /api/users/:id`

Требует сессию, CSRF и Origin. Тело не нужно. Успех — `200 {}`. Удаляет запись и ключи из базы; журнал сохраняет событие с именем. Несуществующий ID — `404`.

### `POST /api/users/:id/rotate`

Требует сессию, CSRF, Origin и JSON. Успех — `200` с публичной записью.

```json
{ "protocol": "all" }
```

Допустимы `all` (значение по умолчанию), `naive`, `mieru`, `vless`, `share`. `all` меняет также ссылку выдачи. `share` отзывает только ссылку и не делает скачанные конфиги недействительными. Остальные три значения меняют секрет одного протокола и сохраняют ссылку выдачи.

## 5. Клиентские комплекты и ссылка выдачи

### `GET /api/users/:id/bundle`

Требует сессию и эффективный статус `active`; иначе `409`. Возвращает JSON:

```json
{
  "files": {
    "naive.json": "JSON_TEXT",
    "mieru.json": "JSON_TEXT",
    "vless.json": "JSON_TEXT",
    "vless.txt": "VLESS_URI_WITH_NEWLINE",
    "README.txt": "CLIENT_INSTRUCTIONS"
  },
  "vlessUri": "vless://…"
}
```

Значения `files` — строки готовых файлов, а не вложенные JSON-объекты. Ответ содержит персональные секреты.

С параметром `?download=1` ответ — ZIP. На самом деле учитывается присутствие параметра `download`, поэтому `?download=0` тоже скачивает архив. Условие синхронизации здесь не проверяется: администратор может готовить конфиги заранее и должен проверить статус сервера отдельно.

```sh
export TRIDENT_USER_ID='ID_FROM_CREATE_RESPONSE'
curl --silent --show-error --fail-with-body \
  --cookie cookies.txt \
  --output client.zip \
  "$TRIDENT_ORIGIN/api/users/$TRIDENT_USER_ID/bundle?download=1"
```

### `GET /api/users/:id/share`

Требует сессию. Возвращает `200 {"path":"/access#TOKEN"}`. API отдаёт относительный путь; добавьте публичный HTTPS-origin панели. Если скопировать origin SSH-туннеля, такая ссылка будет вести на localhost получателя.

Получить путь можно для существующего пользователя любого статуса. Фактическая выдача по нему дополнительно проверяет активность и применение.

### `POST /api/access`

Публичная выдача по секретному токену, административная сессия и CSRF не нужны. Нужны JSON и совпадающий `Origin`:

```json
{
  "token": "PERSONAL_43_CHARACTER_BASE64URL_TOKEN",
  "download": false
}
```

Успех при `download` отсутствующем/ложном:

```json
{
  "name": "Алексей",
  "expiresAt": "2026-10-16T23:59:59.999Z",
  "bundle": {
    "files": {},
    "vlessUri": "vless://…"
  }
}
```

В реальном ответе `files` содержит все пять файлов. При `download: true` возвращается ZIP `trident-access.zip`.

Условия выдачи:

1. Токен — строка из 43 символов `[A-Za-z0-9_-]` и совпадает с текущим токеном пользователя.
2. Пользователь имеет `effectiveStatus=active`.
3. Статус агента свежий, текущая ревизия применена, предупреждений развёртывания нет.

Неверный токен, отключённый/истёкший/удалённый пользователь дают `404`. Неприменённое состояние даёт `409`. Лимит — 30 запросов в минуту на адрес соединения. За штатным Caddy это общий loopback-адрес, поэтому ограничение может затронуть нескольких получателей одновременно.

## 6. Настройки сервера

### `PUT /api/settings`

Требует сессию, CSRF, Origin и JSON. Принимает частичное обновление, проверяет итоговую конфигурацию и возвращает `200` с настройками без приватного ключа.

| Поле | Допустимое значение |
|---|---|
| `host` | Домен без схемы и порта; IP не принимается |
| `naivePort`, `vlessPort`, `panelPort` | Целое число 1–65535 с проверкой пересечений |
| `mieruStart`, `mieruEnd` | 1025–65535, начало ≤ конца, не более 100 портов |
| `naiveQuic` | Boolean; включает HTTP/3 Caddy также для HTTPS-панели |
| `realitySni` | Домен целевого сайта без схемы и порта |
| `realityTargetPort` | Целое число 1–65535; исходящий порт цели, не слушающий порт VPS |
| `acmeEmail` | Пустая строка либо email до 254 символов |

Зарезервированы числа портов 80, 2019, 8787 и 22. Диапазон mieru, NaiveProxy, VLESS и HTTPS-панель не должны пересекаться между собой или с резервом. Сервер нормализует домены в нижний регистр. Неизвестные поля, включая `privateKey`, `publicKey` и `shortId`, при обновлении игнорируются.

Пример частичного изменения:

```json
{
  "host": "proxy.your-domain.tld",
  "acmeEmail": "admin@your-domain.tld",
  "vlessPort": 8443
}
```

Проверка домена синтаксическая: API не проверяет DNS, доступность REALITY target, сертификат или firewall. Смена `host`/`panelPort` сразу меняет допустимый публичный Host backend, поэтому выполняйте её через SSH-туннель и после применения открывайте новый адрес.

## 7. Серверный экспорт

### `GET /api/server-bundle`

Требует административную сессию. Возвращает ZIP `trident-server.zip` с `Caddyfile`, `xray.json`, `mita.json`. Включает только эффективно активных пользователей, но не требует подключённого агента. Файлы содержат пароли и приватный REALITY-ключ. Экспорт не применяет их на сервере.

Этот GET и пользовательский `/bundle` записывают события экспорта в журнал, хотя сами конфиги движков не меняют.

## 8. Ошибки и повторы

| Код | Типичные причины |
|---|---|
| `400` | Некорректный JSON, поля, срок, порт, пересечение диапазонов, протокол перевыпуска |
| `401` | Нет/истекла сессия либо неверный пароль |
| `403` | Недопустимый Host/Origin, отсутствует Origin у изменяющего запроса, неправильный CSRF, удалённый setup |
| `404` | Маршрут/пользователь не найден либо выдача по ссылке недоступна |
| `405` | Неподдерживаемый метод для статической страницы |
| `409` | Администратор уже создан, экспорт неактивного пользователя, сервер ещё не готов к персональной выдаче |
| `413` | JSON-тело больше 32 KiB |
| `415` | У запроса с JSON-телом нет подходящего Content-Type |
| `429` | Ограничение частоты запросов |
| `500` | Необработанная внутренняя ошибка |

Маршруты API с неподходящим методом обычно возвращают `404` после проверки авторизации; общего ответа `405` для всех API-методов нет.

Ключей идемпотентности нет. Автоматический повтор `POST /users` после потери ответа может создать второго пользователя; повтор `/rotate` ещё раз заменит секрет. При сомнительном результате сначала перечитайте обзор, затем решайте, нужен ли повтор. `PUT` предназначен для установки конкретных значений полей.

## 9. Чего API пока не предоставляет

Нет маршрутов для смены пароля администратора, ролей, токенов интеграций, метрик трафика, квот, выбора устройств, горячего применения, управления несколькими серверами и версионированного `/api/v1`. Это внутреннее API текущей панели; при расширении проекта изменения схем нужно согласовывать с интерфейсом и тестами.
